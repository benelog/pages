페이스북 글로 본 정상혁

2026-10-15 · facebook.com/benelog에 올린 글을 Claude Code(Claude Opus)에게 읽히고 분석시킨 결과

읽은 범위: 2019년 중반부터 2026년 10월까지 쓴 글 약 600개. 2019년 이전 글은 페이스북 피드가 더 이상 불러오지 않아 읽지 못했다. 본문이 비어 있던 글 몇십 개와 일부 조각도 빠졌다. 공개된 글만 보고 추론한 결과다.

1. 한 줄 요약

18년째 네이버에서 큰 시스템을 다뤄 온 Java 서버 개발자. 용어와 사실이 정확하지 않으면 그냥 넘어가지 못하는 사람. 지금은 관리자이지만 주말에는 여전히 PR을 올리고, AI 시대에 개발자가 하는 일이 어떻게 바뀌는지를 가장 진지하게 기록하는 사람이기도 하다.

2. 일과 커리어

  • 큰 시스템 전환 전문가. 네이버페이 기술 구조 개편(플라즈마/Platform Labs)에서 대기열, outbox 테이블 복제, 정산 플랫폼(Spring Batch Plus), Fixture Monkey, Scavenger 같은 결과물이 나왔다. "월마다 조 단위 돈이 오가는 시스템", "연간 52조 정산" 같은 표현을 채용 홍보에 쓴다.
  • 관리자가 된 개발자. "12년 전 감탄한 글인데 이제 내가 관리자가 되었구나"라며 경영 원칙 8개를 다시 올렸다. 채용 공고를 자주 공유하고, 면접관과 신입 교육도 맡는다. 2024년에는 "올해는 회사에서 코딩을 안 하다 보니"라고 썼다.
  • 사람의 성장 가능성을 보는 면접관. 채점 시스템에서는 탈락했지만 거침없이 코딩하던 인턴 지원자를 합격시켰는데, 그 사람이 나중에 Linux 커널에 기여하고 DEVIEW에서 발표했다. 이 일화를 길게 남긴 데서 "지금 아는 것보다 앞으로 클 수 있는지"를 본다는 원칙이 드러난다.

3. 생각하는 방식의 특징

① 구체성에 대한 집착 (가장 두드러진 특징)

  • '이슈', '가볍다/무겁다', '디테일하게', '팔로우업' 같은 말을 보면 "메모리를 적게 쓴다는 뜻인가요?"라고 되묻는다.
  • 사례:
    • '종아리 이슈로 알바 쉽니다'라는 말을 들으면 떠오를 질문 목록
    • 장그래 보고서 제목은 '중동 항로 동향'이어야 한다는 의견
    • 'Architector'는 영어 단어가 아니라는 지적
    • 'WIKI'를 대문자로 쓸 근거가 없다는 지적
    • "Boot가 안 붙으면 그냥 못 넘어간다"
  • 본인도 '이슈'를 자주 쓴다고 인정한다. 남에게만 들이대는 기준이 아니라는 점이 신뢰를 준다.

② 사실과 데이터 정합성

  • 예방접종 기록이 실제 맞은 백신과 다르게 들어가자 의사에게 이야기해 바로잡았다. 본인 표현으로는 "직업병"이다.
  • 남의 글에 있는 틀린 내용을 근거와 함께 정정한다.
    • KISA의 Logback 설명
    • Flyway/Liquibase 비교
    • 'ArrayList는 thread safe'라는 서술
    • VO 불변성을 should가 아니라 must로 정의한 책
  • 'the the' 오타 수정 PR, datafaker의 '서태지와 소년'을 '서태지와 아이들'로 고친 PR도 같은 성향이다.

③ 이름 짓기에 대한 관심

  • RestTemplate, RestClient, WebClient의 이름을 직접 다시 지어 봤다.
  • Fixture Monkey는 Fixture Ape로 할 걸 그랬다고 썼다.
  • 회사에만 있는 용어(책임리더)의 비용, 사내 동명이인 23명 문제, 성씨 제도, '백신'이라는 이름이 안티바이러스에 맞지 않는다는 점도 다뤘다.
  • 한국산 JDK 배포판 이름은 칡차, 율무차가 좋겠다는 농담도 있다.

④ 역사와 순서로 기술을 이해

  • SQL Mapper와 ORM은 앞뒤 세대가 아니라 같은 시기에 나왔다고 짚었다.
  • component-scan이 @Configuration보다 먼저 나와서 남용되었다고 봤다.
  • git-flow는 이름 덕에 실제보다 더 퍼졌다고 썼다.
  • 은탄환 비유의 어원도 직접 찾아봤다.
  • 한 기술을 판단할 때 "그게 언제, 무엇의 대안으로 나왔나"를 기준으로 삼는다.

⑤ 트레이드오프로 말하기

  • JIT와 AOT를 시작시간, 메모리, 최대 처리율 등 다섯 축으로 비교하는 그래프를 좋아한다.
  • 기술마다 장단점을 함께 적는다. Native Image, CRaC, CDS의 적용 난이도와 효과, Git LFS와 DVC, Flyway와 Liquibase가 그 예다.
  • "나는 어떤 기준에 트레이드오프가 있다고 말하는 성향이지만, AI 비용을 성과로 포장하는 건 잘못이다"처럼, 유보하는 사람이 단정할 때는 그만큼 근거가 쌓여 있다.

⑥ 낭비를 싫어하는 실용주의

  • 아무도 안 쓰는 냉장고의 전원 코드를 직접 뽑은 일이 있다.
  • 토큰과 데이터센터 전기를 아끼려고 rm은 직접 친다.
  • 196 회문수 계산에 쓰인 전기가 아깝다고 썼다.
  • 커버리지 수치를 조직 목표로 삼는 데 반대하고, PowerMock 사용에도 반대한다.

4. 기술 취향

  • 주력 분야: JVM, Spring, Spring Batch, JDBC 계층과 퍼시스턴스. MyBatis를 7년 넘게 피하고 Spring Data JDBC를 쓰며, SQL 관리에는 Groovy/Kotlin 문자열을 쓴다. 로깅 생태계(SLF4J/Logback)에도 깊이 관여한다.
  • 테스트 중심: 테스트 셋과 소스 중 하나만 고르라면 테스트를 고른다는 인용을 공유했다. Rod Johnson의 '카우보이 개발자' 대목도 인용했다.
  • Linux 데스크톱을 고수:
    • Ubuntu와 Dell XPS 조합을 쓰고, 휴대폰은 Nexus에서 Pixel로 이어 왔다. ChromeOS와 미니PC도 써 봤다.
    • 파워포인트 때문에 Windows VM을 띄우는 것은 "장비의 순수성을 해치는 것 같다"며 망설인다.
    • 장비는 "가성비를 따지다가 레어 아이템을 모으는 재미가 붙었다"고 스스로 말한다.
  • 문서와 지식 관리:
    • 작성은 AsciiDoc, 배포는 정적 사이트로 한다.
    • 지식 관리는 Obsidian으로 하며, "연결이 없는 지식은 머릿속에서도 GC된다"고 썼다.
    • 책은 직접 스캔해서 OCR을 돌리고, Egloos 블로그는 12년 전 댓글까지 옮겼다.
  • 최근 변화: 개인 도구는 Go로 많이 만든다. Claude Code를 Max 플랜으로 쓰고, Hermes + Modal + Telegram으로 개인 에이전트를 운영했다.

5. AI를 대하는 태도 (2023~2026년의 가장 큰 주제)

  • 1단계, 회의 (2023): GPT-4가 질문의 절반 넘게 틀린다고 썼고, "이순신 장군이 빨간 김치를 먹었나"로 모델을 시험했다.
  • 2단계, 각성 (2025): '먼저 온 미래'를 7월에 "올해의 책"으로 정했다. 이세돌의 "다들 나와 같은 실수를 하고 있다"를 인용했다.
  • 3단계, 몰입과 경계 (2025~2026):
    • Claude Code를 개인 돈으로 결제했고, 하루 만에 Max 플랜으로 올릴지 고민했다.
    • 블로그 글을 분석시켜 글쓰기 가이드를 만들었고, '상혁봇' 이야기도 했다.
    • 동시에 AI가 쓴 문장의 추상적 표현을 강하게 비판하고, 그것을 고치는 지침을 계속 보강하고 있다.
  • 스스로 내린 결론:
    • "AI가 만든 초안에 불만을 가질 수 없다면 내가 존재할 이유가 없다." 판단력과 까다로운 취향을 사람의 몫으로 본다.
    • 생산성의 핵심은 "실제 사용 → 피드백 → 재배포" 주기를 얼마나 줄이느냐라고 본다. 큰 스펙을 한 번에 정의하는 방식은 AI 시대에도 실패할 수 있다고 의심한다.
    • "AI가 시간을 절약해 준다는데 나는 컴퓨터 앞에 있는 시간이 더 늘었다"는 솔직한 관찰도 남겼다.

6. 성향과 가치관

  • 기록하고 보존하는 사람: 고등학교 때 만든 DOS 프로그램을 Dosbox로 다시 실행해 봤고, 대학 노트와 월간 마소를 스캔해 두었다. 사라진 프리챌 메일함을 아쉬워한다. 반면 자신이 남긴 데이터는 "3년만 온라인에 두고 이후에는 콜드 스토리지로" 옮기라고 할 만큼 담담하다.
  • 여가 시간에 엄격함: "앞으로 1~2년 여가 활동의 유익성을 엄격히 평가하겠다"며 '폭싹 속았수다'를 안 보기로 했다. "남들 유튜브, 넷플릭스 볼 시간에"라는 말이 반복해서 나온다. 달리기도 KPI(허리 둘레)를 정해 놓고 한다.
  • 기여는 하되 드러내지 않으려 함: 외부 강연료는 전액 기부하고 이를 공개했다. 버스 정류장 스티커를 붙이고 다닌 사람처럼 "이름을 숨기고" 좋은 일을 하고 싶다며 GitHub 제2 계정 이야기를 했다.
  • 자기 풍자와 아재 유머:
    • "설명충 40대 아저씨", "옛날 사람"이라고 자신을 부른다.
    • "그레이들 어셈블!"을 외치고, GitHub에 '더더 봇'(아바타는 박혜경)을 제안했다.
    • 테크 이야기만 올린다던 페이지 정책을 "오늘부터 개발 또는 아이유"로 바꿨다.
  • 대중문화를 개발 상황에 대입함: 탑건 매버릭으로 김부장 개발자 시나리오를 썼고, '나의 아저씨'의 외력과 내력 대사를 부하와 처리율로 바꿔 봤다. 나디아의 네모 선장이 "상관없어"라고 하는 장면은 장애 대응 교재로 본다. NBA 루카 돈치치와 제이슨 키드는 FE/BE 역할 구분 이야기에, 포프의 대모험은 "끝이 명확해야 한다"는 이야기에 썼다.
  • 가족: 큰딸에게 7살 때부터 Entry, Python 순서로 코딩을 가르쳤고, 그 과정을 꼼꼼히 기록했다. 딸이 추천한 책을 읽고 함께 뮤지컬도 본다.

7. 글쓰는 방식

  • 전형적인 흐름: 관찰로 시작해 자기 경험을 붙이고, 일반화한 뒤 "~싶기도 하다"로 유보하며 끝난다. 단정은 드물고, 반례를 스스로 먼저 꺼낸다.
  • 구성: 인용을 먼저 걸고 그 아래에 생각을 붙이는 형식이 많다. 책 쪽수까지 적는다.
  • 말투: 문장 끝에 TT, ;, ..를 자주 쓴다. 진지한 이야기 끝에 자기를 낮추는 한 줄을 붙인다.

8. 흥미로운 모순

겉으로 드러난 주장함께 보이는 반대 모습
구체적인 표현만 좋다허준이 교수의 축사를 "시"로 읽고, 함축적인 표현의 힘을 인정함
비용과 전기를 아낀다레어 키보드와 미니PC를 수집함
나는 옛날 사람이다새 도구(Obsidian, Pijul, Claude Code)를 가장 먼저 써 봄
AI가 쓴 글이 마음에 안 든다내 글도 다음 날 보면 마음에 안 든다

종합

엔지니어링을 바라보는 기준이 일관된 사람이다. 이름과 사실을 정확히 하는 것, 트레이드오프를 따지는 것, 피드백 주기를 줄이는 것, 낭비를 줄이는 것이 회사 일과 취미, 가족 이야기, AI에 대한 생각에 똑같이 적용된다.
